# 売れるアフィリエイトブログの「デザイン・見せ方」分析

調査日: 2026-10-19
表記ルール: **【事実】** は出典に書いてあること。**【推測】** は出典からの筆者（Claude）の考え・業界でよく言われるが今回は裏付けを取れていないこと。

> 先に正直に書いておくこと: 「Rinker と ポチップ でクリック率が何%違う」「ボタンを赤にしたら何%上がった」のような**アフィリエイトブログでの信頼できる測定データは、公開情報ではほぼ見つかりませんでした**。比較記事の多くは機能比較と体感です。数字が出ている事例は少なく、ここでは見つかったものだけを出典つきで載せています。

## 第1部 調査結果

### 1. 商品リンク（Rinker・ポチップ・カエレバ・もしもかんたんリンク）

#### 共通する見た目（4つともほぼ同じ形）
```
┌────────────────────────────────┐
│ [商品画像]  商品名（2行まで）      │
│            メーカー / 価格(取得日時)│
│ [Amazon] [楽天市場] [Yahoo!]      │ ← 店ごとの色のボタンが横に並ぶ
└────────────────────────────────┘
```

| ツール | 事実として確認できたこと | 出典 |
|---|---|---|

| Rinker | ボタンの文言・色の変更はコード（CSS/HTML）が必要。有料版でセール情報（楽天のポイント倍率など）を自動表示 | [bloganswer](https://bloganswer.jp/pocchip-vs-rinker/) / [maipyon](https://maipyon.net/pochipp-vs-rinker/) |

#### なぜクリックされるのか
- **【事実】** Google は商品レビューのおすすめとして「読者が任意の販売者から購入できるように、複数の販売者へのリンクを記載することを検討します」と書いている。→ 3ボタン並びは Google の方針とも合う。([Google 検索セントラル](https://developers.google.com/search/docs/specialty/ecommerce/write-high-quality-reviews?hl=ja))
- **【推測】** 読者は「いつも使う店」（楽天ポイントを貯めている人、Prime会員など）で買いたい。1つの店しかないと「自分の店にはないのかな」で離脱する。3つ並べると、読者は「買うか買わないか」ではなく「**どこで買うか**」を考えるようになる。
- **【推測】** 店ごとの色（Amazon=オレンジ/黄、楽天=赤、Yahoo=青〜紫系）は、読者が見慣れた色なので一瞬で「押す場所」とわかる。※各ツールのデフォルト色について明記した出典は今回取れず。
- **【事実】** ボタン上に「お買い物マラソン開催中」「ポイント◯倍」を出すセール表示が、各ツールの**有料機能の目玉**になっている（＝作者や利用者が効果があると考えている）。maipyon の筆者は体感で「1日100PVのレビュー記事でセール時に500円以上売上が増える」と見積もっているが、測定値ではない。([maipyon](https://maipyon.net/pochipp-vs-rinker/))

#### 数字が出ている事例（少ない）
- **【事実・ただし個人ブログの自己申告】** 楽天アフィリエイトのクリック率が **0.5% → 2.3%**、月の報酬が 5,000円 → 50,000円。やったことは (1)いきなり商品リンクを貼らず「導入→なぜ楽天か→使ってみた→最後に行動を促す」の流れにした (2)「今だけクーポン」「レビュー★4.5以上」「送料無料」を添えた (3)ボタンを冒頭・商品紹介の直後・最後に置き、大きくして「楽天市場で今すぐチェック！▶︎」のような行動の文言にした (4)関連記事への内部リンク。施策ごとの効果は分けて測っていない。([楽天ブログ](https://plaza.rakuten.co.jp/room10yu/diary/202503060004/))

### 2. ボタンの色・文言・位置

#### 色とサイズ
- **【事実】** 緑＝安心・進む、赤＝急ぎ・期間限定、オレンジ＝親しみ（カートに入れる等）。ただし「この色が勝つ」という測定値はない。([SquadBeyond](https://squadbeyond.com/blog/cta_button_design/))
- **【事実】** 大事なのは色そのものより**目立つこと（コントラスト）**。ボタン文字と背景は 4.5:1 以上、ボタンとページ背景は 3:1 以上（WCAG）。白背景に薄いグレーの枠だけのボタンは基準を満たさないことがある。([同上](https://squadbeyond.com/blog/cta_button_design/))
- **【事実】** タップしやすい大きさ: WCAG 2.2 最低 24×24px、推奨 44×44px、Android 48dp。実務の推奨は**高さ48px以上**。([同上](https://squadbeyond.com/blog/cta_button_design/))

#### 位置
- **【事実】** 「商品の魅力を語った直後」「料金表の下」「お客様の声の直後」など**文脈に合わせて置く**。複数箇所（最初・各セクションの終わり・最後）が一般的。([SquadBeyond](https://squadbeyond.com/blog/cta_button_design/))
- **【事実】** 上の楽天ブログ事例でも「冒頭・商品紹介の直後・最後」の3か所。([楽天ブログ](https://plaza.rakuten.co.jp/room10yu/diary/202503060004/))
- **【事実】** 追従ボタン（画面下にずっと出るボタン）は「一定量スクロールしてから出す」のが推奨。iPhone の下部バーに隠れないよう `padding-bottom: env(safe-area-inset-bottom)`、本文が隠れないよう `body{padding-bottom:72px}` などの余白を取る。([SquadBeyond](https://squadbeyond.com/blog/cta_button_design/))
- **【推測】** 追従ボタンは「1商品を強くすすめる記事（レビュー記事）」向き。比較・ランキング記事で1商品だけ追従させると押し売り感が出る。

#### マイクロコピー（ボタンの上や中の短い言葉）
- **【事実・書籍からの孫引き】** 購入ボタンを「予約注文する」→「今すぐ予約購入する」に変えたら CV率 1.5倍（HushTug、『ザ・マイクロコピー』より）。([ミエルカ](https://mieru-ca.com/heatmap/blog/microcopy))
- **【事実・伝聞】** オバマ陣営のサイトでボタンを「SIGN UP」→「LEARN MORE（もっと知る）」にしたらクリック率18%増、と言われている（一次出典なし）。([サングローブ](https://www.sungrove.co.jp/microcopy/))
- **【推測】** この2つから言えるのは「**押した後に何が起きるかがわかる言葉**」「**押すハードルが低く聞こえる言葉**（買う→見る）」が強いということ。アフィリエイトなら「購入する」より「楽天で価格を見る」「公式サイトで今のキャンペーンを見る」の方が押しやすい。

### 3. 人気テーマ（SWELL・AFFINGER・SANGO・JIN）の記事装飾

**【事実】** SWELL の装飾機能（[エックスサーバー SWELLレビュー](https://www.xserver.ne.jp/blog/swell-review/)）:

| 装飾 | 内容 |
|---|---|
| ふきだし | キャラが話しているように見せる。アイコン・向き・色を変更可 |
| キャプション付きボックス | 枠にタイトルをつけた箱。「リストをまとめる用途によく使われる」 |
| リッチカラム | スマホでも2〜4列の横並び |
| テーブル（比較表） | 4スタイル、セルごとの配色、**スマホで横スクロール**、表の中にボタン |
| FAQ | Q&A形式、**構造化データを自動出力** |
| ステップ | 手順を順番に見せる |
| 目次 | 見出しから自動生成、サイドバーに追従させて現在地がわかる |
| ボタン | 5スタイル、**クリック数の計測**つき |
| 星評価 | ★の数を数字で指定 |

AFFINGER・SANGO・JIN も同じ種類の装飾（吹き出し・ボックス・比較表・ランキング・星評価）を持つ。**【推測：今回は各テーマの公式ページを確認していない】**

#### 吹き出しの使い方
- **【事実】** メリット: 本人が話している感じが出て説得力が増す／文章が続く疲れをやわらげる／要点を吹き出しにすると飛ばし読みでも伝わる。注意: 連続は**2往復まで**、1つの吹き出しは**2文まで**。場面を間違えると嫌がられる。([エックスサーバー 吹き出し](https://www.xserver.ne.jp/blog/speech-bubble/))

#### 比較表・ランキングが読まれる理由
- **【事実】** Google の「質の高いレビュー」の方針: 競合商品との違いを説明する／特定の用途に最適なものを説明する／メリット・デメリットを独自の調査で書く／**ランキング（評価順のリスト）は個別レビューを見なくても役に立つ内容にする**／おすすめの理由と自分の体験を書く／定量的な測定結果を出す。([Google 検索セントラル](https://developers.google.com/search/docs/specialty/ecommerce/write-high-quality-reviews?hl=ja))
- **【推測】** 比較表は「スマホで1画面に答えが出る」ので、スクロールに疲れた読者が最後に頼る場所。だから表の中にボタンを入れる。

#### 導入文の効果（装飾より強い）
- **【事実・個人ブログの自己申告】** 導入文を書き換えたら平均滞在時間が 3分30秒 → 9分3秒（約2.6倍）。吹き出しや装飾ではなく、導入で「悩みに共感→この記事で何がわかるか」を示したのが理由とのこと。([なべけん](https://nabeken.substack.com/p/2-6-1281246))

### 4. スマホでの読みやすさ

- **【事実】** 国内メディアの実測: スマホ本文は 14〜18px、**16pxが約6割**。行間は 1.6〜2.0em、**1.8emが最多**。h1 はスマホ 20〜24px。筆者の推奨は本文 16px・行間 1.8、h1 はスマホ 24px・行間 1.3。([アソボウズ](https://blog.asobou.co.jp/web/fontsize))
- **【推測（業界の通説、今回は数字の一次出典なし）】** 1文は40〜60字くらい、1段落は2〜3文（スマホで3〜5行）。見出しが来るまで画面3〜4回分スクロールさせない。画像や表・ボックスなど「文字以外のもの」をスマホ1〜2画面に1つ。

### 5. AIっぽく見える文章・デザインの特徴

**【事実】** 出典に書かれていた特徴:
- 語尾がそろって単調／「まず」「しかし」「さらに」の連続／構造がきれいすぎて教科書的／感情や筆者の視点がない／箇条書きが多い／強調記号（*）が残る／「いかがでしたか？」([スマートウォッチライフ](https://www.smartwatchlife.jp/60468/))
- 文の長さがそろう／定型句の使い回し／「多くの人が」「研究によると」など出典のない一般論／個人の体験がない ([howmanywords](https://howmanywords.app/ja/ブログ/AI文章を人間らしくする方法))
- 「導入→3〜4段落→箇条書き→要約の結論」という型／「まとめると」「結論として」で締める／最も一般的で当たり前な論点を選ぶ／具体性のない賛辞が均一に並ぶ ([Pangram](https://www.pangram.com/ja/blog/how-to-detect-ai-writing))
- 独自性・ユーモア・個人的なストーリーがない／著者がわからない ([ギズモード](https://www.gizmodo.jp/2024/01/how-to-identify-ai-generated-sentences.html))
- 避け方として: 体験・具体的な場面・数字・固有名詞を入れる／短い文と長い文を混ぜる／意見を言い切る／**体験談を捏造しない**／最後は人が読み直す ([howmanywords](https://howmanywords.app/ja/ブログ/AI文章を人間らしくする方法) / [スマートウォッチライフ](https://www.smartwatchlife.jp/60468/))

**【推測】** デザイン面でAIっぽく見えるもの: すべての見出しの下に同じ形の箱がある／どの記事も同じ構成・同じ装飾の順番／絵文字の見出し／フリー素材やAI生成のきれいすぎる画像だけで実物写真がない／「メリット3つ・デメリット3つ」がいつも同じ数／著者情報がない。

### 6. ルール面（デザインに直接関わるもの）
- **【事実】** 2023年10月からステマ規制。PR表記は**ファーストビューなど最初に目に入る場所**に、見やすい文字の大きさ・色で。使える文言は「広告」「PR」「プロモーション」「本ページはプロモーションが含まれています」など。「AD」「sponsored」はわかりにくいのでNG。([富士山マガジンサービス](https://www.fujisan.co.jp/guidance/guideline/stealth_marketing_regulation))
- **【推測・要確認】** 楽天ウェブサービス（API）は利用規約でクレジット表示が求められている。具体的な形式は Rakuten Developers の規約で確認すること。

## 第2部 まとめ（中学生でもわかる言葉で）

### 1) 売れるデザインの原則 トップ10

1. **買える店を3つ並べる** — 人は「いつもの店」で買いたい。店が1つだと、そこを使わない人は帰ってしまう。Google も複数の店へのリンクをすすめている。
2. **ボタンはひと目で「押す場所」とわかる色と大きさに** — 色の種類より、まわりと違って目立つかが大事。高さ48px以上、指で押しやすく。
3. **ボタンの言葉は「押したら何が起きるか」を書く** — 「購入」より「楽天で今の価格を見る」。見るだけなら押しやすい。
4. **ボタンは「ほしい」と思った直後に置く** — 冒頭（結論）、商品の紹介の直後、まとめ。読み終わってから探させない。
5. **最初の画面で答えを出す** — 「結論：◯◯がおすすめ。理由は△△」を冒頭に。スマホの読者は答えを早く知りたい。
6. **比較表で「自分に合うもの」を選ばせる** — 読者は迷っている。表なら1画面で違いがわかり、そのまま押せる。
7. **体験の証拠を見せる** — 自分で撮った写真、測った数字、使ってみてダメだった点。Google も「画像や自分の体験」を信頼の証拠として求めている。
8. **悪いところも書く** — 良いことだけだと宣伝っぽくて信じてもらえない。「こういう人には向かない」と書くと、向いている人が安心して買う。
9. **スマホで読み疲れない形** — 文字16px、行間1.8、短い段落、ときどき表や箱で息つぎ。
10. **広告であることは最初に正直に書く** — 法律（ステマ規制）で決まっているし、隠すと信用を失う。

### 2) 当ブログにすぐ入れるべきパーツ（優先度つき）

前提: Jekyll（`_includes` で部品化）、自作CSS、楽天APIで写真つき商品カード、記事は毎朝AIが書く。

**A-4. 本文の基本CSS（スマホ優先）**

- 星評価は**根拠を書いた項目だけ**つける（何でも★4.5はAIっぽい・信用されない）。

#### 優先度C（様子を見て）

**C-1. 吹き出し** — 使うなら「読者の疑問役」1人だけ、1記事に2〜3回、1つ2文まで。
```html

```
AIが毎朝書くと吹き出しを多用しがちなので、**上限を決めてテンプレート側で制限**する。

**C-2. 追従ボタン（レビュー記事のみ）** — 30%スクロール後に表示、まとめの位置で非表示。
```css

```

**C-3. クリック計測** — ボタンに `data-pos="top|mid|table|bottom"` をつけ、GA4 のイベントで位置別クリック数を見る。SWELLのボタンにも計測機能があるのは、**位置と文言は測って直すもの**だから。データが溜まったら文言を2パターンで比べる。

#### ボタン文言の例（マイクロコピー）

| 場所 | ボタン | ボタンの上の小さな一言（例） |
|---|---|---|
| 冒頭 | 楽天で今の価格を見る | 楽天ポイントが貯まる |
| 商品紹介の直後 | 楽天市場で詳細を見る | レビュー◯件・平均★4.3（APIの値をそのまま） |
| セール中 | 楽天で今のセール価格を見る | お買い物マラソン ◯日まで |
| サービス系 | 公式サイトで今のキャンペーンを見る | 初月無料は◯月◯日まで |
| まとめ | ◯◯を楽天で見る（商品名を入れる） | 迷ったらこれ。返品◯日OK |

**ウソの限定・ウソの数字は書かない**（「残りわずか」「今だけ」は本当のときだけ）。数字はAPIから取った値か、公式に書いてある値のみ。

### 3) AIっぽさを消すためのルール

#### 文章のルール（毎朝のAIのプロンプトに入れる）
1. **最初の3行で結論とおすすめの相手を言い切る。** 「〜について解説します」「〜と悩んでいませんか？」から始めない。
2. **禁止フレーズ**: 「いかがでしたか」「〜と言えるでしょう」「〜することが重要です」「まず／次に／さらに／最後に」の連続、「結論として」「まとめると」、「様々な」「多くの人が」「〜の世界」。
3. **語尾を3回続けてそろえない。** 「です。です。です。」をやめ、言い切り・問いかけ・体言止めを混ぜる。
4. **短い文と長い文を混ぜる。** 10字の文のあとに50字の文、くらいの差をつける。
5. **固有の数字を最低3つ入れる。** 価格・重さ・サイズ・レビュー件数など（APIの値で可）。「軽い」ではなく「約480g（500mlペットボトルくらい）」。
6. **デメリットを必ず1つ以上、具体的に。** 「人によっては合わないかも」ではなく「本体が幅30cmあるので一人暮らしのキッチンだと置き場所に困る」。
7. **体験はでっち上げない。** 使っていないものを「使ってみた」と書かない。AIが書く記事は「調べてまとめた」「レビュー◯件を読んで多かった声」と**正直に書く**。これはステマ規制・景品表示法の面でも安全。
8. **箇条書きは1記事3か所まで。** 残りは普通の文章で、理由と一緒に書く。
9. **毎回同じ構成にしない。** 「結論→比較表→個別紹介→FAQ→まとめ」を毎日続けると、サイト全体がAIっぽく見える。記事の種類ごとに2〜3種類の型を用意してローテーション。
10. **強調記号（`**` や `*`）・絵文字見出しを残さない。** 出力後に機械的にチェックする。

#### デザインのルール
1. **装飾は「意味があるときだけ」。** 箱・吹き出し・マーカーを各見出しに1つずつ置かない。1記事の装飾ボックスは3〜5個まで。
2. **画像は商品写真（API）＋自作の図や表。** AI生成の人物イラストやきれいすぎるイメージ画像をアイキャッチ以外に使わない。
3. **著者・運営者情報を明記。** 「誰が・どうやって選んだか」（例:「楽天のレビュー件数と評価、価格を毎朝確認して選んでいます」）を記事下とプロフィールに。AIを使っている事実も隠さず、どこを人が確認しているかを書く。
4. **価格・ランキングには取得日時。** 毎朝更新している強みを「◯月◯日 7:00更新」と見せる。
5. **色は3色まで**（文字の黒・アクセント1色・楽天赤などボタン色）。何色も使うと素人っぽく、テンプレっぽくもなる。
6. **ボタンは記事あたり3〜5か所まで。** 段落ごとにボタンがあると押し売りに見える。
